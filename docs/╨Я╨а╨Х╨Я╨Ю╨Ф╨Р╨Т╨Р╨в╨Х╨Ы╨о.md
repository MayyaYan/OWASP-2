# Настройка GitHub Classroom с автопроверкой (для преподавателя)

## Коротко

1. Залейте этот репозиторий на GitHub и сделайте его **шаблонным**
   (Settings → ✅ Template repository).
2. В GitHub Classroom создайте assignment и укажите этот репозиторий как
   **starter code**.
3. Автопроверка уже встроена (`.github/workflows/classroom.yml` +
   `.github/classroom/autograding.json`) — Classroom подхватит её.

Ниже — подробно.

---

## Шаг 1. Подготовка стартового репозитория

1. Загрузите файлы (см. [`ЗАГРУЗКА_НА_GITHUB.md`](ЗАГРУЗКА_НА_GITHUB.md)).
2. **Settings → General → Template repository** — включите галочку.
   Теперь репозиторий можно раздавать как шаблон.

## Шаг 2. Создание классы и задания

1. Откройте https://classroom.github.com → войдите → создайте **Classroom**
   (привязывается к вашей организации на GitHub).
2. **New assignment** → задайте название, тип (Individual / Group), срок.
3. В разделе **Starter code repository** выберите этот репозиторий.
4. В разделе **Add autograding tests**:
   - Classroom прочитает готовый файл `.github/classroom/autograding.json`,
     либо вы добавите тесты вручную через кнопку **Add test → Run command**.
   - Для ручного добавления используйте такие команды (Run command test):

     | Test name | Setup command | Run command | Points |
     |---|---|---|---|
     | Отчёт заполнен | `pip install pyyaml` | `python tests/check.py report` | 10 |
     | Скриншоты (мин. 5) |  | `python tests/check.py screenshots` | 10 |
     | IDOR | `pip install pyyaml` | `python tests/check.py idor` | 15 |
     | Forced Browsing | `pip install pyyaml` | `python tests/check.py forced` | 15 |
     | Privilege Escalation | `pip install pyyaml` | `python tests/check.py privesc` | 15 |
     | JWT | `pip install pyyaml` | `python tests/check.py jwt` | 10 |
     | Классификация OWASP | `pip install pyyaml` | `python tests/check.py category` | 10 |

5. Сохраните. Classroom выдаст ссылку‑приглашение для студентов.

## Шаг 3. Что увидит студент

- Получает персональный репозиторий — копию шаблона.
- Запускает Codespace, выполняет 4 сценария.
- Заполняет `answers/answers.yml`, отчёт и кладёт скриншоты.
- При `git push` запускается `classroom.yml`; баллы видны во вкладке
  **Actions** и в панели Classroom у преподавателя.

## Как устроена автопроверка (чтобы вы могли её менять)

- `tests/check.py` — один скрипт, принимает имя проверки
  (`idor`, `forced`, `privesc`, `jwt`, `category`, `report`, `screenshots`).
  Печатает `PASS: ...` и код 0 при успехе, иначе `FAIL: ...` и код 1.
- Эталонные ответы хранятся **не открытым текстом**, а в виде `sha256`
  (словарь `EXPECT`). Это мешает студенту просто прочитать ответ из файла.
- Проверки `report` и `screenshots` оценивают полноту сдачи (наличие
  разделов, отсутствие незаполненных мест, минимум 5 изображений).

### Поменять эталонный ответ

Пересчитайте хэш и впишите его в `EXPECT`:

```bash
python3 - <<'PY'
import hashlib, re
def norm(s): return re.sub(r'\s+','',s.strip().lower())
print(hashlib.sha256(norm("НОВЫЙ_ОТВЕТ").encode()).hexdigest())
PY
```

### Про защиту от списывания (честно)

Скрипт проверки лежит в репозитории студента, поэтому полностью скрыть
логику нельзя — это общее ограничение GitHub Classroom. Хэширование
усложняет подбор, но мотивированный студент может его обойти. Поэтому:

- основные баллы завязаны на **процесс** (заполненный отчёт + скриншоты
  запроса/ответа), который подделать труднее, чем значение в `answers.yml`;
- при желании вынесите «секретные» проверки в приватный репозиторий и
  вызывайте их через отдельный workflow, который клонирует приватные тесты
  по токену (`secrets`), — тогда эталоны студенту не видны.

## Локальная проверка перед раздачей

```bash
pip install pyyaml
# впишите верные ответы в answers/answers.yml и проверьте:
for c in idor forced privesc jwt category report screenshots; do
  python3 tests/check.py $c
done
```

Либо используйте сторонний локальный прогон `autograding.json`
(например, `gh-grader-preview`), чтобы увидеть результат как на GitHub.
