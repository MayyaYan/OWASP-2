# Практическая работа: Тестирование безопасности веб‑приложения

## Поиск уязвимостей нарушения контроля доступа (Broken Access Control)

> Учебная лаборатория запускается прямо в **GitHub Codespaces** — установка
> ничего локально не требуется. Мишень — официальное учебное уязвимое
> приложение **OWASP Juice Shop**.

[![Open in GitHub Codespaces](https://github.com/codespaces/badge.svg)](https://codespaces.new/)

---

## 1. Цель работы

Научиться запускать уязвимое веб‑приложение в изолированной среде, перехватывать
и изменять HTTP‑запросы и самостоятельно находить уязвимости класса **«Нарушение
контроля доступа»** (Broken Access Control). Этот класс занимает **первое место**
в актуальном рейтинге **OWASP Top 10:2025**.

## 2. Что вы научитесь делать

- запускать учебную среду в GitHub Codespaces (без локальной установки);
- отправлять и изменять HTTP‑запросы прямо из редактора (REST Client);
- находить и подтверждать минимум **4** уязвимости контроля доступа;
- запускать **автоматическое** сканирование безопасности через GitHub Actions (OWASP ZAP);
- оформлять отчёт со скриншотами и классификацией по OWASP Top 10:2025.

## 3. Важное предупреждение (правила этики)

> ⚠️ Атаковать разрешено **только** эту учебную лабораторию в вашем Codespace.
> Сканирование и атаки на чужие сайты без письменного разрешения владельца —
> **незаконны**. Juice Shop специально создан для легального обучения.

---

## 4. Запуск лаборатории (3 способа — выберите один)

### Способ A — GitHub Codespaces (рекомендуется, ничего ставить не нужно)

1. Нажмите зелёную кнопку **Code → Codespaces → Create codespace on main**.
2. Подождите 1–2 минуты. Среда сама скачает и запустит Juice Shop.
3. Когда появится уведомление о порте **3000** — нажмите **Open in Browser**.
   (или вкладка **PORTS** → строка 3000 → значок глобуса).
4. Откроется магазин Juice Shop — это ваша мишень.

Подробности и устранение неполадок: [`docs/SETUP.md`](docs/SETUP.md).

### Способ B — локально через Docker

```bash
docker run --rm -p 3000:3000 bkimminich/juice-shop
# затем откройте http://localhost:3000
```

### Способ C — локально через docker compose

```bash
docker compose up
```

## 5. Инструменты внутри Codespace

Вам не нужен Burp или ZAP с графическим интерфейсом — всё делается в браузере и редакторе:

| Инструмент | Для чего | Где находится |
|---|---|---|
| **REST Client** (VS Code) | Отправлять и изменять HTTP‑запросы | файлы в папке [`requests/`](requests/) |
| **Браузерные DevTools** (F12) | Смотреть запросы, cookie, токены | вкладка Network / Application |
| **curl** | Запросы из терминала | терминал Codespace |
| **GitHub Actions + OWASP ZAP** | Автоматическое сканирование | вкладка Actions репозитория |

> Папка `requests/` содержит готовые `.http`‑файлы. Откройте любой, и над каждым
> запросом появится ссылка **Send Request** — нажмите её, чтобы отправить запрос
> и увидеть ответ сервера. Чтобы провести атаку, достаточно изменить одно число
> или одно поле и нажать Send ещё раз.

## 6. Основное задание — 4 сценария

Выполните все четыре. Для каждого сделайте **скриншоты** (запрос + ответ) и
запишите вывод в отчёт [`reports/REPORT_TEMPLATE.md`](reports/REPORT_TEMPLATE.md).

Полезно открыть **доску прогресса** Juice Shop — она показывает, какие уязвимости
вы уже нашли: `http://<ваш-адрес>:3000/#/score-board`.

### Сценарий 1. IDOR — доступ к чужой корзине
Подмена идентификатора объекта в запросе даёт доступ к чужим данным.
- Файл запросов: [`requests/01_idor_basket.http`](requests/01_idor_basket.http)
- Что сделать: войти, посмотреть свой запрос `GET /rest/basket/{id}`, затем
  изменить `{id}` на соседний и проверить, вернулись ли **чужие** товары.

### Сценарий 2. Forced Browsing — вход в админ‑панель
Прямой переход на скрытую страницу без прав.
- Файл: [`requests/02_forced_browsing.http`](requests/02_forced_browsing.http)
- Что сделать: будучи обычным пользователем, открыть
  `http://<адрес>:3000/#/administration` и проверить доступ.

### Сценарий 3. Privilege Escalation — регистрация администратора
Приложение доверяет роли, присланной клиентом.
- Файл: [`requests/03_privilege_escalation.http`](requests/03_privilege_escalation.http)
- Что сделать: в запросе регистрации `POST /api/Users` добавить поле
  `"role": "admin"` и проверить, получили ли вы права администратора.

### Сценарий 4. Анализ JWT‑токена
- Файл: [`requests/04_jwt_analysis.http`](requests/04_jwt_analysis.http)
- Что сделать: найти токен в заголовке `Authorization`, декодировать его на
  [jwt.io](https://jwt.io/) и описать, какие данные он хранит и чем опасна
  подделка при отсутствии проверки подписи.

Если застряли — подсказки (не готовые решения) в [`docs/HINTS.md`](docs/HINTS.md).

## 7. Автоматическое тестирование в среде GitHub (OWASP ZAP)

В репозитории настроен workflow, который сам поднимает Juice Shop и сканирует его
пассивным сканером OWASP ZAP.

1. Откройте вкладку **Actions** вашего репозитория.
2. Выберите workflow **«Автоматическое сканирование безопасности (OWASP ZAP)»**.
3. Нажмите **Run workflow**.
4. После завершения скачайте артефакт **zap-baseline-report** (HTML/JSON‑отчёт).
5. Приложите выводы сканера к отчёту и сравните их с тем, что вы нашли вручную.

Конфигурация: [`.github/workflows/zap-scan.yml`](.github/workflows/zap-scan.yml),
правила: [`.zap/rules.tsv`](.zap/rules.tsv).

## 7a. Автопроверка (GitHub Classroom)

Если преподаватель выдал работу через **GitHub Classroom**, ваш репозиторий
проверяется автоматически при каждом `git push`.

Что нужно сделать для зачёта автопроверки:
1. Заполнить файл [`answers/answers.yml`](answers/answers.yml) (ответы по 4 сценариям).
2. Заполнить отчёт [`reports/REPORT_TEMPLATE.md`](reports/REPORT_TEMPLATE.md).
3. Положить **минимум 5 скриншотов** в папку [`screenshots/`](screenshots/).
4. Сделать commit и push — проверка запустится сама.

Результат смотрите во вкладке **Actions** (зелёная галочка ✅ или красный крест ❌)
или по значку статуса рядом с коммитом. Баллы распределены так же, как в
разделе «Критерии оценки».

> Настройка со стороны преподавателя описана в
> [`docs/ПРЕПОДАВАТЕЛЮ.md`](docs/ПРЕПОДАВАТЕЛЮ.md).

## 8. Что сдать (отчёт)

Заполните шаблон [`reports/REPORT_TEMPLATE.md`](reports/REPORT_TEMPLATE.md):

1. Описание среды (Codespace / Docker), скриншот запущенного Juice Shop.
2. По каждому из 4 сценариев: шаги, скриншоты запроса/ответа, вывод.
3. Результат автоматического сканирования ZAP (скриншот + краткий разбор).
4. Таблица найденных уязвимостей: подтип, категория OWASP, мера защиты.
5. Общий вывод: что эффективнее — ручной анализ или автосканер, и почему.

Скриншоты складывайте в папку [`screenshots/`](screenshots/).
